# UI_Detection_model_training

Trains a YOLO detector that finds and classifies UI elements in OTT streaming
app screenshots, using a locked 16-class taxonomy.

Output: a versioned model bundle consumed by the separate `ui_comparision`
repo, which does the actual Production-vs-Client comparison.

## Scope

**In:** label remap, dataset prep, training, evaluation, error analysis,
model packaging.

**Out:** OCR, VLM, fusion, matching, difference detection, reporting. Those
belong to `ui_comparision`.

## Data

The 103 labeled screenshots are client data and are **never committed**.

```
data/
├── images/        # gitignored — 103 screenshots
├── labels_22/     # gitignored — original Label Studio export, read-only
├── labels_16/     # gitignored — generated by scripts/remap_labels.py
```

Check before every commit:

```bash
git status --short

```

## Setup

```bash
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Training runs on Colab (T4, 16 GB). Local verification runs in the
`ui_compare_v2` container on the GTX 1070.

## Build order

Phases are in `BUILD_PROMPTS.md`, one prompt per phase for Claude Code.

| # | Phase | Output |
|---|---|---|
| 0 | Scaffold | folders, gitignore, config |
| 1 | Label audit | report on the raw 22-class labels |
| 2 | Remap 22 → 16 | `data/labels_16/`, `config/classes_16.txt` |
| 3 | Visual verification | annotated previews — **confirm before training** |
| 4 | Dataset split | `ds/`, `config/ui.yaml`, class-aware split |
| 5 | Smoke run | proves the plumbing, not the accuracy |
| 6 | Full training | Colab notebook, `best.pt` |
| 7 | Evaluation | per-class table, confusion matrix, worst cases |
| 8 | Error analysis | diagnosis before any tuning |
| 9 | Package bundle | `models/ui16_v1/` + verification script |
| 10 | Improve | one experiment at a time, logged |

Phases 1, 3, and 8 end with "show me and wait." Those are the points where
proceeding on a wrong assumption costs the most.

## The taxonomy

16 classes, order is binding — see `CLAUDE.md` and `docs/INTERFACE.md`.

Three classes (`rank_number`, `text_input`, `logo`) have single-digit training
examples. They will score badly. That is a data limitation, not a model bug,
and the consuming pipeline covers them with a VLM fallback.

## Handoff

```bash
python scripts/package_model.py --run runs/ui16 --version v1
python scripts/verify_bundle.py models/ui16_v1     # must exit 0
```

The bundle contract is `docs/INTERFACE.md`. Read it before changing anything
that crosses the repo boundary.
